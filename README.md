# CiviMind — интеллектуальный анализ тональности текста

CiviMind — учебный проект по разработке и развёртыванию ИИ-приложения в Kubernetes. Приложение определяет тональность русскоязычного текста с использованием локальной модели машинного обучения.

Проект реализован на Java и Spring Boot, упакован в оптимизированный Docker-образ и развёрнут в Kubernetes с автоматическим масштабированием и мониторингом.

## 1. Возможности приложения

- Анализ тональности текста через REST API.
- Определение положительной, отрицательной и нейтральной тональности.
- Возврат результата классификации и оценки уверенности модели.
- Веб-интерфейс для отправки текста на анализ.
- Локальная работа ML-модели без обращения к внешним ИИ-сервисам.
- Мониторинг состояния приложения и метрик JVM.
- Горизонтальное масштабирование в Kubernetes.

## 4. Модель машинного обучения

Для классификации тональности используется модель логистической регрессии с векторизацией текста TF-IDF.

Обучение и эксперименты выполнялись на Python с использованием scikit-learn. Основой послужил датасет RuSentiTweet.

В ходе разработки сравнивались несколько вариантов модели, включая разные способы извлечения текстовых признаков.

Для итоговой интеграции модель экспортирована в JSON и загружается непосредственно Java-приложением.

**Результаты экспериментов:**

| Эксперимент | Accuracy |
|---|---:|
| Модель v3, тестовая выборка RuSentiTweet | 61,01% |
| Модель v4, тестовая выборка RuSentiTweet | 67,39% |
| Модель v3, независимая выборка обращений | 46,67% |
| Модель v4, независимая выборка обращений | 44,44% |

Для интеграции выбрана модель v3, показавшая более высокий результат на независимой выборке обращений.

Полученные результаты показывают ограничения переноса модели с коротких сообщений социальных сетей на тексты другой предметной области. Поэтому CiviMind рассматривается как учебный прототип, а не как готовая система для принятия значимых решений.

## 5. REST API

Основной endpoint:

```http
GET /api/sentiment?text=Прекрасный день
```

Пример запроса:

```powershell
Invoke-RestMethod "http://localhost:8080/api/sentiment?text=Отличный%20день"
```

Приложение возвращает JSON с определённой тональностью и оценкой уверенности модели.

Также поддерживается POST-запрос для анализа текста.

## 6. Локальный запуск

Требования:

- Java 17;
- Maven;
- Docker Desktop для контейнерного запуска.

Сборка приложения:

```powershell
mvn clean package
```

Запуск без Docker:

```powershell
java -jar target/civimind-1.0.0.jar
```

После запуска приложение доступно по адресу:

```text
http://localhost:8080
```

## 7. Docker

Для оптимизации Docker-образа применены:

- многоэтапная сборка;
- создание минимальной Java Runtime через jlink;
- использование базового образа scratch;
- копирование только необходимых системных библиотек и приложения.

Сборка финального образа:

```powershell
docker build -f Dockerfile.minimal -t civimind:final .
```

Пример локального запуска с временной файловой системой:

```powershell
docker run --rm -p 8085:8080 --tmpfs /tmp civimind:final
```

Веб-интерфейс после запуска контейнера:

```text
http://localhost:8085
```

**Результаты оптимизации:**

| Образ | Размер |
|---|---:|
| Первоначальный | 307 МБ |
| Оптимизированный | 156 МБ |
| Финальный | 145 МБ |

Размер финального образа уменьшен примерно на 52,8% относительно первоначального и соответствует ограничению менее 150 МБ.

## 8. Развёртывание в Kubernetes

Проект тестировался в локальном Kubernetes-кластере Docker Desktop.

Перед развёртыванием необходимо собрать образ `civimind:final` и убедиться, что он доступен контейнерной среде кластера.

Создание namespace:

```powershell
kubectl create namespace civimind
```

Применение манифестов:

```powershell
kubectl apply -f k8s/
```

Проверка:

```powershell
kubectl get pods -n civimind
kubectl get deployment,hpa -n civimind
kubectl get svc,ingress -n civimind
```

В Deployment настроены три реплики приложения.

Service использует тип LoadBalancer, а Ingress обеспечивает маршрутизацию запросов `/api` через NGINX Ingress Controller, который устанавливается отдельно.

В локальной конфигурации для доступа через Ingress использовался NodePort `31035`.

Пример запроса:

```powershell
Invoke-RestMethod "http://localhost:31035/api/sentiment?text=не%20очень%20понравилось"
```

## 9. Автоматическое масштабирование

В Kubernetes настроен Horizontal Pod Autoscaler.

Основные параметры:

- минимальное число реплик — 3;
- максимальное число реплик — 6;
- целевая загрузка CPU — 50%.

Для проверки масштабирования временно использовался сниженный порог CPU 2% и создавалась тестовая нагрузка.

Во время эксперимента число реплик увеличилось с 3 до 6. После проверки целевой порог был возвращён к 50%.

## 10. Мониторинг

Для мониторинга приложения использованы Spring Boot Actuator, Micrometer, Prometheus и Grafana.

Endpoints:

```text
/actuator/health
/actuator/prometheus
```

Prometheus собирает метрики приложения из Kubernetes.

В Grafana создан дашборд **CiviMind Monitoring**, содержащий панели:

1. JVM Heap Memory — использование памяти JVM.
2. CPU Usage — использование CPU.
3. JVM Garbage Collection — показатели сборки мусора.

Prometheus и Grafana развёрнуты с использованием Helm в namespace `monitoring`.

## 12. Ограничения

CiviMind является учебным прототипом.

Качество классификации зависит от предметной области и особенностей текстов. Модель, обученная на сообщениях социальных сетей, может ошибаться при анализе официальных обращений и других специализированных документов.

Для практического использования необходимы расширение обучающей выборки, дополнительная разметка данных и повторная оценка качества.
